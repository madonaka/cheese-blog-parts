# 2026-08-04 회의 — 학습 뷰어 화면 회수(브라우저 UI vs 우리 UI)

> 참여: 치즈랩 대표, Claude
> 주제: 학습 뷰어에서 브라우저 주소창이 안 사라지는 이유를 규명하고, 태블릿 가로모드에서 화면 위쪽을 3층(탭 바·주소창·제어바)이 먹는 문제를 어떻게 회수할지 정한다

---

## 배경 (왜 이 회의를 했나)

네이버 같은 사이트는 스크롤하면 주소창이 접히는데 우리 학습 뷰어는 아무리 넘겨도 주소창이 그대로 남는다는 관찰에서 시작했다.
처음엔 브라우저별 차이나 설정 문제인가 싶었으나, 실제 원인은 우리 레이아웃이었다.

이어서 대표가 진짜 불편한 지점을 특정했다 — **핸드폰은 괜찮은데 태블릿 가로모드가 심하다.** 세로가 짧은 화면에서 페이지 탭·주소창·우리 제어바 세 층이 상시로 쌓이니, 정작 본문이 받는 세로 공간이 콘텐츠 양에 비해 과도하게 좁다.

---

## 오늘 정한 것 (결론)

1. **태블릿 가로모드 문제는 "브라우저 UI"와 "우리 UI"를 따로 친다.**
   상단 3층 중 탭 바·주소창은 전체화면 API로만 없앨 수 있고, 제어바는 100% 우리 통제 하에 있다. 하나의 묘수가 아니라 두 갈래 작업이라는 걸 확인하고 티켓도 둘로 쪼갰다.

2. **학습 뷰어 제어바에 전체화면 토글 버튼을 넣는다.**
   태블릿 가로모드의 탭 바는 스크롤로 절대 접히지 않는(데스크톱형 UI) 층이라, 스크롤 기반 해법은 처음부터 답이 될 수 없다. 독자가 버튼을 누르면 탭 바·주소창·하단 내비바가 전부 사라지고 본문이 화면 100%를 차지한다. 자동 진입은 브라우저가 막으므로 **반드시 사용자 탭으로만** 발동한다.

3. **제어바 자동 숨김/탭 토글을 함께 한다(체감상 이쪽이 더 클 수 있음).**
   전체화면은 독자가 눌러야 발동하지만, 제어바 숨김은 누구에게나 기본으로 적용된다. 리더 앱 표준대로 넘길 땐 안 보이고, 탭하면 나타났다 잠시 뒤 사라지는 방식으로 간다.

4. **PWA(홈 화면에 추가)는 보류한다.**
   주소창을 확실히 없애는 유일한 방법이지만, 독자가 "홈 화면에 추가"를 할 만큼 콘텐츠에 붙어 있는지 데이터가 없는 상태에서 설치 유도 UI부터 만드는 건 순서가 거꾸로다. 위 두 건으로 태블릿 문제가 실질적으로 풀리면 굳이 설치를 요구할 이유가 없다.

---

## 아직 안 정한 것 (다음에, 필요해지면)

- `theme-color`로 브라우저 UI 색을 본문에 맞추는 안(회의 초반의 D안). 주소창이 사라지진 않고 "튀지 않게"만 하는 처치라, 위 두 건을 넣고 나서 여전히 거슬리는지 보고 판단.
- 제어바를 되살리는 정확한 조작(화면 중앙 탭 vs 상단 탭 vs 위로 스와이프)과 자동으로 다시 숨는 시간.
- 전체화면 상태를 기억해 다음 방문에 안내할지 여부. 새로고침하면 어차피 풀리는 게 브라우저 규칙이라, 재진입 유도가 필요한지는 써 보고 판단.
- PWA 도입 시점. 재방문·완독 데이터가 쌓여 "설치할 만큼 붙어 있다"가 보이면 그때 다시 꺼낸다.

→ 세 건 모두 **T-030·T-031을 실제로 태블릿에서 써 본 뒤** 판단한다.

## 확인된 구조 (이번에 OK 난 것)

| 항목 | 상태 | 방식 |
|------|------|------|
| 주소창이 우리 뷰어에서 안 접히는 이유 | 규명 | 브라우저의 주소창 자동 숨김은 **문서(body) 자체가 스크롤될 때만** 발동한다. 우리 뷰어는 한 화면 고정 + 탭으로 넘김 + `overflow:hidden`이라 문서 스크롤이 아예 없다. 브라우저 탓이 아니라 레이아웃 구조상 당연한 결과 |
| 브라우저별 차이 | 확인 | 크롬(안드로이드)·사파리(iOS)·삼성인터넷·파이어폭스 전부 "문서 스크롤 기반 자동 숨김"으로 전제가 같다. 접히는 부위(상단/하단)만 다름 |
| 태블릿 가로모드 탭 바 | 확인 | 데스크톱형 UI라 스크롤로 **절대** 안 사라진다 → 전체화면 외에 경로 없음 |
| iOS 전체화면 API | **정정 + 보류** | 회의 초반 "아이폰은 Fullscreen API 불가"는 옛 정보였다. Safari 16.4에서 macOS·iPadOS가 무접두사 정식 지원으로 올라섰고 아이폰도 이후 버전에서 열렸다. 다만 기기·버전별로 갈리므로 **버전을 믿지 않고 기능 감지(`requestFullscreen`/`webkitRequestFullscreen` 존재 여부)로 처리**하고, 미지원 기기에서는 버튼을 아예 노출하지 않기로 했다 |
| 슬라이드 넘김이 페이지를 새로 여는가 | 확인 | **아니오.** `learn/viewer.js`는 DOM만 교체하고 URL을 건드리지 않는다(`location` 변경은 나가기·카테고리 이동·로그인 리로드에서만). 따라서 전체화면이 슬라이드마다 풀리지 않는다 — 전체화면 안을 계속 유지 가능 |
| 우리 제어바 위치 | 확인 | `learn/viewer.html`의 `.learn-progress-header` — 나가기·제목·카운터 + 버튼 6개(목차·자동넘김·노트·공유·야간·스크롤). 전체화면에 들어가도 이 줄은 남으므로 별도 처리 필요 |
| 전체화면의 제약 | 확인 | ① 자동 진입 불가(사용자 제스처 필수) ② 위에서 아래로 스와이프·뒤로가기로 언제든 빠져나옴(갇히지 않음) ③ 새로고침하면 해제 |
